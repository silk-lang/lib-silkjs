### The last commit, and one parked patch

1. **Site shapes probe** (`modules/engine/src/js_vm_property_ops.silk` `readSiteShapes`, called from
   `readField` in `modules/engine/src/js_compiled_objects.silk`). The optimizer already records up to
   four shapes per get-field site (`CompiledTable.siteShapes`). When compiled code misses its inline
   check and calls `jitGetField`, the engine now probes that same table before the generic path.
   Own entries read `key & 0xffff`; prototype entries also need `epochs[i] == state.shapeEpoch`
   and the holder's shape version to match. Result: 4.283G to 4.240G Ir, jitGetField from about
   300 to about 100 instructions per call.
2. **Dead locals, parked** as `docs/jit/patches/dead-locals.patch` (apply with `git apply`; it touches only
   `modules/jit/src/ssa_translate.silk`: : `Liveness`, `livenessOf`, `localEffect`,
   `dropDead`, `afterInstruction`). A backward liveness pass over the bytecode (one u64 bit per
   local, functions with at most 64 locals and no catch, gosub, ret, close_loc or make_loc_ref).
   When a local dies, the translator releases its value and replaces it with undefined, so the
   refcount of a dead object drops early and exits write undefined into its cell. The aim is the
   retain and release churn around local `c` in `Plan.execute` (function 70).
   **Measured: no gain** (4.240G to 4.246G, release count unchanged). Releasing early does not
   remove the pair: the read of `c` for the call still retains and the death releases. What
   would pay is making the last read of a local a move (take the local's reference instead of
   retaining, and leave undefined behind). The liveness pass in the patch is the input for that.
3. **Profiling tools** in `modules/jit/prof/` (see "Profiling").

Not yet run on the site shapes change: the 12-minute differential. Run it first (command below).

## Measuring

- **Instructions first.** `valgrind --tool=cachegrind --cache-sim=no` totals on a release shell.
  Compare release with release; a dev build includes the slow dev compiler.
- **Wall time** only on a quiet machine (no build, no valgrind running): interleaved medians of
  15 pinned runs, more than one round. Single runs swing in clusters because of the host.
  Equal-instruction builds can differ by 4 to 7% from code layout alone.
- `modules/jit/prof/opt/rel.sh NAME` builds a release shell, profiles DeltaBlue x20 with callgrind
  and prints the total and the top optimized functions.
- `modules/jit/prof/opt/dbtry.sh NAME [scripts]` builds a dev shell and prints DeltaBlue x60
  counters (inlined, frame exits, refused, bytes), optionally with the scripts and Richards.
- `modules/jit/prof/bench/five_engines.py` takes the five-engine table (interpreter, baseline,
  optimizer, V8, V8 jitless). Results so far are in `docs/jit/jit-scorecard-results/2026-11-21-five-engines/`.
  `http_modes.py` and `http_stats.py` do the same for the HTTP order service.

The tools write their outputs next to themselves (`SILKJS_PROF` overrides the directory); those
outputs are gitignored.

## How the optimizer frame works (short)

- Registers: r13 runtime header, r12 BaselineEnv, rbx the cell base (`localAt(0) + 128`), r14 the
  argument cells. Values live in 16-byte stack slots and are always spilled.
- Exits are table driven and the exit records name values by id: a value's slot must be valid at
  every exit that names it, and never forward a copy to its source in SSA.
- Prologue: inline stores into the record and StackFrame (code, state, currentFunction, this,
  argv, argc), `argumentsData` borrowed from rsi unless the function copies arguments or is
  called with fewer than it declares (then `STUB_PROLOGUE`). The record's spare word keeps the
  caller's rbx. Return is inline unless arguments are owned (`STUB_LEAVE`) or the frame was built
  (state above `FRAME_BARE_CONSTRUCT`).
- Optimized functions have their hotness parked at 2^31-1.
- SiteShapes: up to four entries per site; a prototype holder is valid only while
  `RuntimeState.shapeEpoch` is unchanged. `RuntimeState.polyFields` is getter-only: probing it for
  data reads made things slower.
- More detail: `docs/jit/optimizer.md`, `docs/jit/baseline.md`, `docs/jit/ssa.md`.

## Traps

- No source edits while a build is before the `borrow` line of its log, and never two builds at once.
- Silk: `effect` and `run` are keywords (no locals with those names). `u64.shiftLeft` and
  `shiftRight` take a u64 right operand. OWN0010/OWN0011: compute an argument into a local
  before a call that borrows the same object mutably.
- When you patch files with Python string replace, assert the replace count.
- Code counts move 4% with the script path's length: compare builds with the same absolute path.
- RegExp interpreter counts have two levels depending on the environment size; rerun with
  `env -i PAD=xxx` of a few lengths before blaming a change.
- Assembler branch relaxation moves offsets taken with `offset()`: use `finishPlaced`.
- A stub's slow path assumes the stub's own stack alignment: keep rsp = 8 mod 16, plus one word
  around each call.
- To commit a verified state while newer edits are in the tree: copy the files aside when the
  checks start, then `git hash-object -w` and `git update-index --cacheinfo`.
- AOT must stay possible: refer to engine code through symbols and relocations, not raw addresses.
